As respostas de erro documentadas usam um objeto JSON com `error` (tipo resumido) e `message` (explicação legível). O texto exato pode variar conforme a causa.

## Códigos documentados

| Código | Significado na API | O que conferir |
| --- | --- | --- |
| `400 Bad Request` | Corpo ausente ou inválido; em atualização, status inválido ou campos ausentes. | Confira JSON, campos obrigatórios e valores permitidos. Para status, use `pending`, `in_progress` ou `done`. |
| `401 Unauthorized` | Chave de API ausente ou inválida. | Envie `Authorization: Bearer <sua_chave_de_api>`. Veja [Autenticação](/authentication). |
| `404 Not Found` | Projeto ou tarefa não encontrado. | Confira se o ID veio de uma resposta de criação e se está sendo usado na rota correta. Crie o projeto antes de criar tarefas. |

Os códigos acima são os definidos na especificação para as operações correspondentes. Respostas de sucesso: `201` ao criar projeto ou tarefa e `200` ao listar, atualizar ou excluir.

## Dependências do fluxo

- Crie o projeto antes de criar tarefas. A criação de projeto retorna o `project_id`.
- Use o `project_id` para criar tarefas e listar as tarefas do projeto.
- Use o `task_id` retornado ao criar uma tarefa para atualizá-la ou excluí-la.
- A exclusão é permanente.

## Tempo de resposta inicial

O servidor pode levar até 60 segundos para responder à primeira requisição. Aguarde a resposta antes de reenviar uma operação de criação, pois uma nova tentativa pode criar outro recurso.

## Limitações conhecidas na especificação

- A especificação lista somente cinco operações: criar projeto; criar, listar, atualizar e excluir tarefas. Consulte o grupo **Referência da API** na navegação.
- Não há operações documentadas para listar projetos, consultar uma tarefa individual, recuperar uma tarefa excluída ou gerenciar chaves de API.
- O contrato não documenta paginação, filtros, limites de requisição ou política de repetição. Não presuma a existência desses recursos.
