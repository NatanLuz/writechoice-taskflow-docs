---
title: "Authentication"
description: "Send your TaskFlow API key with Bearer authentication and keep it secure."
---

All operations require a valid API key in the HTTP `Authorization` header, formatted as `Bearer <key>`.

## Send the header

```http
Authorization: Bearer <your_api_key>
```

With cURL, load the key from an environment variable:

```bash
export TASKFLOW_API_KEY="<your_api_key>"
curl --request GET \
  --url "https://test-writechoice.onrender.com/projects/<project_id>/tasks" \
  --header "Authorization: Bearer $TASKFLOW_API_KEY"
```

In PowerShell, set the variable with `$env:TASKFLOW_API_KEY = "<your_api_key>"` and use `$env:TASKFLOW_API_KEY` in the header value.

## Protect your API key

- Do not include your key in source code, repositories, screenshots, or public examples.
- Do not share the key or include it in URLs. Send it only in the `Authorization` header over HTTPS.
- Use environment variables or a secret manager suitable for your environment.
- If a key is exposed, contact the API owner for guidance on replacing or revoking it. The specification does not document API key management endpoints.

## Authentication errors

A missing or invalid key returns `401 Unauthorized`. Check that the header uses the `Bearer` prefix, has no extra spaces, and contains a valid key. See [Errors and limitations](/errors).
